# 登録・設定画面の最小化 設計

- 日付：2026-11-05
- 対象：SITE EXAM（`wordpress-qa/harness`）の登録画面（`ui/public/registration.js`）と設定画面（`ui/public/settings.js` と組み込みの部品）

## 1. 目的

登録・設定画面の項目が多すぎて使いにくい。利用者の言葉：「自動設定でカバーできる部分のみでよいので、最低限の設定のみ残して大部分をなくしたい」。

## 2. 決めたこと（私の判断。利用者は質問を省いて進めることを選んだ）

**画面に残す項目**

登録画面：
1. サイト名
2. サイトURL
3. 環境（検証／本番／ローカル）
4. サイト閲覧パスワード（閲覧保護がある場合）
5. 「管理画面にログイン」ボタンとその状態表示
6. 検索エンジンへの公開を期待する（初期値：本番＝チェックあり、検証・ローカル＝なし。環境を変えたら初期値を取り直す。利用者が自分で触ったあとは取り直さない）
7. 「ログインを確認して登録・検査を準備」ボタン

設定画面：
1. サイト情報（サイト名、サイトURL、環境）
2. 検索エンジンへの公開を期待する（標準操作テストが登録済みのサイトで表示。未登録なら出さない）
3. サイト閲覧パスワード（新しいパスワード／保存済みを削除）
4. 管理画面へのログイン（「WordPressにログイン」「ログインを確認して保存」と状態表示。共有版の遠隔ログイン画面を含む）
5. 「自動取得してClaudeで補完」（AI が使えるときだけ）
6. 保存・キャンセル

「AI・接続先の設定」は管理者だけが使うので、今回は変えない。

**画面から外す項目**

上に挙げた以外のすべて。例：タイムゾーン、言語、ログインパス、管理画面パス、記事URL構造、URL取得上限、読込上限、テスト用メール、操作許可のチェック、自動取得したフォーム項目、銀行振込注文、自動取得と追加条件、追加のロール認証、共通の操作テスト、公開ページの検査、管理設定の検査、機能・運用の検査、REST API の認証、ロール別の認証、その他の検査（詳細設定）、保存前の実行準備の一覧。

- 操作許可（テスト投稿・フォーム送信・機密ファイル確認・表示上限）は、結果画面の「次にやること」で設定する。
- 外した項目は**消さずに**、画面の一番下の閉じた区画「詳細設定（技術担当向け）」の中へまとめて移す。中身と動きは今のまま。
  - 理由：保存済みのサイトの値を失わない／技術担当が必要なときに直せる／既存のテストと保存処理をそのまま使える。
- 区画の見出しの下に「通常は変更不要です。自動取得と結果画面の『次にやること』で設定されます。」と書く。

## 3. 守ること

- 保存処理・API・保存形式は変えない。画面に出していない値も、今までどおり保存時にそのまま送る（値が消えないこと）。
- 「詳細な検査設定を開く」（`#registration-advanced`）の動きは変えない（既存のブラウザーテストが使う）。
- 既存のブラウザーテストは、閉じた区画を開く1手順を足す程度の修正で通ること。テストの検査内容を弱めない。
- 本番環境で検索エンジンへの公開の初期値をチェックありにするのは、新規登録のときだけ。保存済みのサイトの値は変えない。

## 4. 作り手に任せること

- 区画の作り方（`<details>` に既存の要素を移す、など）。
- 画面の文言の細部。
- 新しいテスト：登録画面と設定画面で、初期表示で見える入力欄が上の一覧だけであること、詳細設定を開くと従来の項目があること、環境の切り替えで検索エンジンの初期値が変わること、詳細設定に触れずに保存しても既存の値が残ること。
