WordPress・PHPの診断機能

2026-10-30 ／ SITE EXAM_ 共有版更新資料

担当者の操作

  1. 対象サイトの設定で、管理画面にログインして保存します。サイトヘルス、プラグイン、テーマを閲覧できる権限が必要です。
  2. 「検査を実行」で「すべて」を選びます。4項目が自動で追加されます。個別再検査は結果の詳細から実行できます。
  3. 結果で構成情報・バージョン・照合日時・未確認事項を確認します。不合格には対象ソフトウェア、CVE（付与されている場合）、出典、対応方法を表示します。

何を検査するか

  • WordPress本体：サイトヘルスのバージョンを公開脆弱性情報と照合。
  • テーマ・プラグイン：管理画面のインストール済み一覧を照合。無効・未使用のものも含みます。プラグイン一覧のページ送りにも対応します。
  • PHP：Webで実行中のPHPバージョンと公式の通常・セキュリティサポート期限を確認。公式サポート終了は要対応として報告します。

対象は通常の単一サイト管理画面です。MUプラグイン、drop-in、ネットワーク全体、独自改変の同一性は確認範囲外です。独自製品や情報源未収録、判定できない版表記、認証切れ、通信失敗は安全と判定せず未確認として残します。

既知脆弱性の影響バージョンとの照合であり、攻撃成立や侵害の証明ではありません。全CVEの収録は保証しません。PHPは系列のサポート期限の診断であり、最新パッチや今回登録したPHP2shell以外のPHP CVE、OS配布元のバックポート・延長サポートの確認は含みません。

管理画面からの対応

本体は「ダッシュボード → 更新」、プラグインは「プラグイン」、テーマは「外観 → テーマ」で修正版を確認します。バックアップと検証環境での互換性確認後に更新し、再診断してください。修正版がない場合は停止・削除・代替を技術担当者と判断します。PHPは通常、サーバー・ホスティング管理画面で変更します。WordPress管理画面だけでは更新できません。

Linux共有版の接続設定

既存データを保持する通常の更新手順で配布ZIPを配置・再ビルドしてください。環境設定・暗号鍵・利用者・保存ボリュームを置き換えないでください。

「AI・接続先の設定」の接続先許可に、次の2つのHTTPSオリジンを追加します。社内IPの指定は不要です。既存の接続先は残してください。

  • https://www.wpvulnerability.net
  • https://www.php.net

今回の照合はClaudeを使わず、追加APIキーも不要です。外部にはWordPressのバージョン、テーマ・プラグインの識別子を照会します。管理Cookie、パスワード、サイトヘルス全文は送信しません。送信元サーバーのIPは通信先に見えます。

根拠となる情報源

  • WPVulnerability 公開API・利用条件・データの限界
  • PHP公式サポート期限

検査は管理画面の読み取りのみです。サイトの更新・設定変更・攻撃リクエストは行いません。

認証の確認と保存

登録済みサイトは、管理画面にログイン後「ログインを確認して保存」を押すと、自動検査用の認証保存まで完了します。設定画面の追加保存は不要です。確認に使ったブラウザーの更新後のCookieを保存します。新規サイトはサイト登録時に保存されます。

Cookieのブラウザー上の期限とは別に、WordPress内部の認証期限があります。内部期限切れは保存時・ソフトウェア診断時に明示します。期限切れの認証を自動延長することはできません。ログインを取得し直す場合は、このツールの専用ブラウザーを使用してください。

公式情報による補助照合

公開脆弱性APIで判定できないWordPress本体は、WordPress公式の最新版APIと比較します。SWELLは公式アップデート一覧から公開版と出典を取得して比較します。今後登録するサイトにも自動適用します。

子テーマは管理画面の親テーマ名から一意に対応付けます。子テーマ名だけから親を推測せず、親が未確認なら未確認と表示します。独自PHP・JavaScript・上書きテンプレートの安全性は親の結果から推定しません。

補助照合が完了してもCVEの未確認範囲が残る場合は「直接確認」です。通信失敗・公式情報を取得できない場合は「実行不能」、既知脆弱性を検出した場合は不合格を維持します。公式最新版との一致は全脆弱性の不在を意味しません。

Linux共有版では「AI・接続先の設定」に https://api.wordpress.org と https://swell-theme.com を追加してください。既存の接続先は残します。追加APIキーは不要で、管理画面Cookieは公式情報源に送りません。

子テーマ独自コードの検査

「検査を実行」のテーマ検査で、管理画面のテーマエディターから取得可能な子テーマを自動検査します。入力値の直接出力、コマンド・SQL・動的ファイル読み込みへの直接受け渡しなどを調べ、ファイル名・行番号・対応方法を表示します。検出は要確認で、脆弱性の確定や安全性の保証ではありません。

最大30ファイル、1ファイル1MiB、合計2MiBです。コード全文は保存・外部送信しません。取得できない範囲を表示し、検査のためにエディターを有効化することはありません。修正は技術担当者が検証環境で行ってください。
