# 観点の網羅とサイト登録時のケース生成

## 必要観点を台帳から消さない

スキルに検査機能があること、サイトへケースを登録したこと、今回実施したこと、合格したことを区別する。各観点を「適用・適用外・未判定」で整理し、適用観点はケースID、期待値、対象、方法、証拠へ対応付ける。未判定を削除やrequired:falseで解消しない。適用外は理由・根拠・判定者を記録する。必要観点の母集団が確定する前に網羅率100%と表現しない。

## サイト登録UI

新規登録画面は共通31観点の設定待ちケースとデザイン確認を生成する。保存時には入力済み各ページへ1280/390pxの表示検査も補完する。HTTP/metadata、内部リンクはpagesから既存のcatalogが生成する。保存は検査実行や外部への送信を伴わない。同じ生成処理を再度適用してもIDを重複させず、入力済みの期待値・ケースを上書きしない。

生成されたunconfiguredケースは、実行するとblockedになる。完成した自動テストではない。UIの「設定を編集」で検査方法・対象・期待値・認証を設定する。管理設定はadminの具体的な項目へ展開し、元の設定待ち行は対応するケースの登録を確認して整理する。非該当はhuman-reviewに切り替え、根拠付き適用外判定を残す。

表示検査は入力済みURLに限る。サイト全体の自動発見ではない。仮のready:bodyは主要コンテンツの準備完了を保証しないため、表示完了条件と代表選定を設定待ちケースで必ず確認する。基準画像は人が承認してから比較を実行する。自動生成の完了と、サイト固有のテスト設計の完了を混同しない。

## 専門領域ごとの補完

| 領域 | 必要な対応付け |
|---|---|
| 管理 | 一般・表示・コメント・パーマリンク・利用プラグインの期待値。観測値を仕様としてコピーしない |
| URL監査 | CMS・サイトマップ・旧URLの突合、全対象リンク元、title内容/description/lang、検索公開、404/転送、robots/OGP/構造化データ、外部/動的リンクの適用判定 |
| 操作 | 正常、必須/形式/境界値、戻る/再送/連打/失敗、検索/メニュー、通知と自動返信、計測/同意、添付/reCAPTCHAの適用判定 |
| EC | 送信前、注文確定、受注登録、通知、取消/後片付けを独立ケースにする。対象決済方式を守り、各注文の識別子で照合 |
| 表示 | テンプレート＋内容例外、商品/一覧/問い合わせ/注文途中など状態別、画面幅、表示完了、画像/フォント/JS/横はみ出し/axe/画像比較 |
| 手動・拡張 | キーボード・読み上げ・実機・文章、投稿/認可/キャッシュ/予約/復元/更新/性能/会員/多言語の適用判定 |

## 結果の検算

preview成功は送信前まで、完了画面成功は画面まで。通知・受注・取消の未確認が公開条件に残っていることを検算する。以前の注文の取消や別のrunのメールを今回の証拠にしない。生成ケース数とカバーした機能数は別に報告する。未設定はblocked、未実施はnot_run、基準画像/手動判断はreviewを維持する。通信の終了処理エラーをサイト不具合へ読み替えない。
