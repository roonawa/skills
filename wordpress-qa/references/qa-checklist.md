# QA観点と実装範囲

この一覧は検査漏れの確認用。組込機能と案件別に追加する検査を区別する。ハーネスの設定に登録されていない項目は実行も結果記録もされない。

| リスク | 組込または専門Skill | 案件で補う検査・人の確認 |
|---|---|---|
| ページ表示・リンク | audit: HTTP、HTML、title、同一originのa[href]。visual: JS例外、可視img読込 | soft 404の内容、背景画像、外部リンク、JS生成リンク、ハッシュ、主コンテンツ |
| SEO・公開 | audit: canonical完全一致、indexable、任意のtitle/description/lang完全一致。discover: sitemap URL一覧 | robots.txt、bot別指示、OGP、構造化データ、サイトマップ掲載漏れ、検索効果、JS生成meta |
| フォーム・通知 | journeyモジュールで入力・送信・エラーをassert。MailpitはTo/件名/本文/件数 | 自動返信、添付、Cc/Bcc、実配送、送信失敗、二重送信、境界値を必要に応じて追加 |
| メニュー・検索 | journeyで操作と到達結果をassert | キーボード/フォーカス、該当なし、特殊文字、検索結果の妥当性 |
| 計測 | journeyで通信を監視し期待イベントをassert | 同意状態別の仕様、測定先、重複、サーバー側計測、実GA画面での受信 |
| reCAPTCHA | 制御可能な検証設定でフォーム処理を検査 | 実設定の接続と判定。Bot判定の精度を自動テストだけで保証しない |
| 管理画面・公開API | policiesに許容ステータスと期待転送先を指定 | ログイン・認可・2FA・用途別の公開方針。ログイン画面があるだけで脆弱性とはしない |
| 機密・防御 | policiesで禁止文字列とヘッダーの期待値を照合 | ソース漏洩、nonce検証、権限別の拒否、既知脆弱性評価、設定の有効性。存在検査は防御の証明ではない |
| レスポンシブ | visual: 指定画面幅の横はみ出し・画像比較 | 必須CTAの存在、実機、他ブラウザー、余白感・視認性 |
| アクセシビリティ | visual: axeのWCAG A/AA | キーボード・読み上げ、代替文の意味、操作の理解しやすさ |
| 性能 | 組込なし | Lighthouse等で測定条件・性能予算を固定して評価。専用ジョブにする |
| 運用 | 組込なし | コア/テーマ/プラグイン更新、バックアップと復元、監視、ロールバック |

## 選定例

お問い合わせフォーム変更では、フォームの表示だけでなく、必須/形式エラー、正常送信、誤宛先・未着、二重送信、計測の必要性を確認する。アップロード機能があれば拡張子・サイズ・権限・通知添付を追加する。機能のない項目は理由付きで適用外とする。

公開前にページが一般検索へ出るべきか、検証サイトが検索へ出ないべきかを分けて設定する。robotsタグの存在やh1の個数だけを普遍的な公開条件にしない。XML-RPCはGET応答からPOSTの無効化を推定しない。

## 安全な検証範囲

本番への連続ログイン試行、実データを使った破壊的変更、許可されていない外部メール送信は実施しない。実効性検査が必要なら、許可範囲と隔離環境・テストデータ・復元手段を用意してから実施する。
