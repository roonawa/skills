# chub-team-status

C-HUB の CS部3ボードと品質保証ボードを読み取り専用で集計する。レポート上、小林・竹内・山口は開くまで中身を隠す（`render_html.py` の `FOLDED_MEMBERS`）。C-HUB が正本で、このスキルはタスクを保持・更新しない。

## 使い方

- 実行: `python scripts/run.py`（このスキルのフォルダで。引数なしで、**毎回 HTML レポートまで作る**）
- `report`（または `レポート`）を付けても同じ。互換のために受け付けるだけで、挙動は変わらない
- オプション: `--today YYYY-MM-DD`（基準日）、`--stale-days N`（動きなしの日数、既定 14）

実行すると `%LOCALAPPDATA%\chub-team-status\runs\<日時>\` に `raw.json`・`aggregate.json`・`dashboard.html` が保存される（最新5回分を残す）。最後に出るパスを使う。

## 答え方

1. 実行して、出力された `aggregate.json` を **読む**。生データ（`raw.json`）を自分で数えない
2. `incomplete` が true、または `warnings` があれば、**何より先に伝える**（取得できなかったボードがある＝数字は全体ではない）
3. 質問があれば、`aggregate.json` から答える（`members` と `unassigned` がレポートの元）:

   | 質問 | 見る場所 |
   | --- | --- |
   | 「◯◯さんのタスク状況は？」 | `members` のその人。`projects`（案件ごとの件数）・`overdue`・`stuck`・`stale`・`nodue` |
   | 「今週の期限切れは？」 | `members` 全員の `overdue`（超過日数の長い順） |
   | 「詰まり／動きなし／期限未設定は？」 | `members` 全員の `stuck`／`stale`／`nodue` |
   | 「担当なしのタスクは？」 | `unassigned`（保守関連の稼働中の契約が多い。別に数える） |
   | 「手が空いている人は？」 | `members` の `open` が少ない人。期限切れ・詰まりの有無も添える |
   | 「商談状況・ゲート違反」 | `deals`（レポートには載せていない。聞かれたときだけ答える） |

4. 質問がないとき、またはレポートを求められたときは、会話に **基準日・メンバー別の期限切れ／詰まり／動きなし／期限未設定の件数・担当なしの件数・目立つ点3つまで** を出す。全件の一覧は会話に書かず、レポートに任せる
5. どの場合も、最後に **`dashboard.html` のパス** を伝える（質問に答えたときも省かない）。ファイルを表示できる環境なら、その場で開いて渡す

## レポート（dashboard.html）の形

定例会議でメンバーごとのタスク状況を確認するための形。上から「一覧表 → メンバー別の欄 → 担当なし」。

- 会議室のスクリーンに映す前提で、画面では文字を大きくしてある（本文 20px。印刷時だけ 12px）。サイズは `scripts/render_html.py` の `_CSS` で変える。小さくしないこと（テストが 20px 未満を弾く）

- メンバー欄は次の5つに分ける: 抱えているプロジェクト（案件名ごとの件数）／期限切れ／詰まり／動きなし（◯日間更新なし）／期限未設定。該当がなければ「なし」と1行で出す
- 担当なしはメンバーとは別枠。保守関連の担当なし（稼働中の契約など）は折りたたむ
- 案件名はタスク名の先頭「◯◯：」（全角・半角のコロン）。無ければボード名（「CS部」「企画/内部」「保守関連」）。「山洋」と「山洋電気」のような表記ゆれは別の案件として出る（直すなら C-HUB のタスク名を揃える）
- 載せないもの: ガント、完了実績、商談の段階別件数、ゲート違反、負荷の表。集計 JSON には残してあるので、聞かれたら会話で答える

### タスクのリンク

- 形は `scripts/links.py` の `TASK_URL_TEMPLATE`（`{base_url}/?view=task-manager&taskId=<タスクID>`。C-HUB の「リンクをコピー」で確認済み）
- 空にするとリンクなしで出る（レポート上部に「未設定」と出る）
- C-HUB 側の URL が変わってリンクが開かなくなったら、タスクを開いて詳細パネルの「リンクをコピー」で得た URL に合わせて直す。画面のアドレスバーは移動しても変わらないので、そこからは取れない

## 判定の意味

| 判定 | 条件 | 保守関連ボード |
| --- | --- | --- |
| 期限切れ | 期限が基準日より前 | 対象外 |
| 詰まり | 状態名が「詰まり」 | 対象 |
| 動きなし | 最終更新から N 日以上（既定 14） | 対象外 |
| 期限未設定 | 期限が空（担当あり） | 対象外 |
| 担当なし | 担当者が空 | 対象（唯一の判定） |
| ゲート違反 | CS部で見積中以降なのに確認状況が「客先すり合わせ済み」でない（集計のみ） | 対象外 |

- 対象は未完了のタスクだけ。CS部の失注・保留（区分またはセクション）は除外し、件数だけ別枠
- 全ボード共通で、セクションが「中止」のタスクと、ステータスが「保留」のタスクは表示しない（集計にも含めない）
- 1件が複数に当たる場合、同じタスクが複数の欄に出る（件数は欄ごとに数える）
- 保守関連ボードは契約管理で期限を持たないため、担当なしの判定以外を行わない

## 注意

- 設定（接続先とキー）は `%LOCALAPPDATA%\chub-team-status\config.json`。**キーの書き込みは Claude Code を閉じて行う**。キーが会話に出たら C-HUB の「AI とつなぐ」で失効・再発行する
- 401 はキー・接続先の違い、403 は権限不足（`task-manager:read`）
- `URLError`（想定外のエラー）で止まる場合は、証明書の検証失敗を疑う。Windows の証明書ストア `CurrentUser\CA` に期限切れの `ISRG Root X2`（拇印 `151682F5218C0A511C28F4060A73B9CA78CE9A53`）が残っていると、Python が正しいチェーンを失効と誤判定する。TLS 検証を切って回避しない。ストアから該当の失効済み証明書を削除する（削除はユーザー自身が行う）
- C-HUB の API は、プロジェクトの表示名が `title`、`archived` が文字列 `"0"`/`"1"`、セクション名は `/projects/{id}/sections` で取る。取得で 0 件になったら、まずこの形が変わっていないか確かめる
- テストは `python -m unittest discover -s tests`（このスキルのフォルダで）。コードを直したら必ず通す
- 詳細は `chub-team-status_設計書.md`
