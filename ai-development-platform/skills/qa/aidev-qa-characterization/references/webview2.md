# WebView2 の画面の記録

Windows のデスクトップアプリが WebView2 に Web の画面を表示している場合に読む。画面そのものは Web なので Playwright で操作できるが、ブラウザを自分で起動するのではなく、実際のアプリの中の WebView2 に CDP（Chrome DevTools Protocol）で接続する。通常のブラウザで同じ URL を開いて動かした結果は、アプリの中での動作の記録にならない。アプリが WebView2 に渡すもの（host object、独自の User-Agent、クライアント証明書）がブラウザにはないためである。

この参照資料は、接続、ログイン、ブラウザとの違いを扱う。ケースの範囲、マニフェスト、証跡の決まりは SKILL.md と他の参照資料のとおりである。

## WebView2 と aidev-qa-desktop-gui の境目

テストは WebView2 の中の DOM の操作と、Windows 側の GUI の操作に分け、同じ spec に混ぜない。

| 操作 | 扱い |
|---|---|
| DOM での入力、検索、一覧の選択、Web のダイアログ | この Skill で Playwright を使って記録する |
| `<input type="file">` へのファイルの指定 | OS のダイアログを出さずに `setInputFiles` で渡せると小さく確かめられたときだけ、この Skill で扱う |
| 決めておいたフォルダへ無人で保存される帳票 | 無人で保存されることを確かめられたときだけ、この Skill で扱う |
| 保存、フォルダ選択、印刷の OS のダイアログ、外部アプリ（表計算、PDF ビューア）、IME | マニフェストで `native-required` にし、aidev-qa-desktop-gui に渡す |
| WebView2 の外のネイティブのログイン画面（証明書方式など） | 起動とログインを aidev-qa-desktop-gui で行い、ログインした後のアプリに接続する |

Playwright のテストの中で FlaUI や UI Automation を呼ばない。OS へのキー送信、座標でのクリック、ウィンドウの前面化や移動もしない。これらは PC の操作を占有し、作業者の操作とぶつかる。Windows 側の操作が必要なものは、PC を占有する時間を作業者と決めて、aidev-qa-desktop-gui で別に流す。

実行中に予期せずネイティブのダイアログが出たら、そのケースを止める。閉じるために勝手にクリックせず、同じインスタンスで後のケースを続けない。

## CDP を有効にして起動する

WebView2 は環境変数 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` にブラウザの引数を受け取る。テスト用に起動するアプリのプロセスにだけ、次を渡す。

```powershell
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = "--remote-debugging-port=$port"
$env:TEMP = $testTemp; $env:TMP = $testTemp   # 作業者のインスタンスとユーザーデータのフォルダを分けるとき
$proc = Start-Process -FilePath $exe -PassThru
```

- 空いているポートを選び、起動したプロセスの ID とポート、exe の版、起動の時刻を記録する（例 `runs/<YYYYMMDD>-<run-id>/launch-<環境>.json`）
- 環境変数は起動するプロセスにだけ渡し、OS の恒久的な環境変数にしない。CDP のポートはローカルでだけ使い、外に公開しない。CDP につながれば、ログイン中のアプリを誰でも操作できる
- アプリが自分で `AdditionalBrowserArguments` を指定している、またはリリースのビルドで環境変数を消している場合は、引数が効かない。どのビルドで効くかを、アプリのソース（WebView2 の環境を作る箇所）で確かめる。効かないビルドを推測の設定で動かそうとしない
- ユーザーデータのフォルダ（userDataFolder）を作業者のインスタンスと共有すると、既存のブラウザのプロセスに相乗りして引数が効かない。アプリが一時フォルダの下に固定で作る場合は、子のプロセスにだけ専用の `TEMP` と `TMP` を渡して分ける
- 起動の後、`http://127.0.0.1:<port>/json/list` に対象のページが出るまで、期限を決めて待つ。同時にプロセスが生きているかを見て、消えたら待つのをやめる

本格的に書き始める前に、代表の画面1つで次を小さく確かめ、結果をプロファイルの本文か QA リポジトリの knowledge に残す。確かめないまま全画面に広げない。

- 環境変数で CDP が有効になるか
- ログインを通せるか。起動のたびに閲覧データが消えるアプリでは、毎回の準備の仕方
- スクリーンショット、ダウンロード、トレースが CDP の接続で取れるか。取れないものは証跡の制約として記録し、取れたことにしない
- 起動のときにフォーカスを奪うか、ネイティブのダイアログや外部アプリが出るか
- 動いているアプリと画面の版（exe、DLL、画面に出る Web の版）が、読んだソースと合っているか

## 接続する

```ts
import { chromium } from '@playwright/test';

const browser = await chromium.connectOverCDP(`http://127.0.0.1:${port}`);
const context = browser.contexts()[0];
if (!context) throw new Error('WebView2 のコンテキストが見つからない');
const page = context.pages().find(p => {
  const url = new URL(p.url());
  return url.origin === targetOrigin && url.pathname.startsWith(appBasePath);
});
if (!page) throw new Error('対象の環境のページが見つからない。ログインが済んでいないか、別の環境に接続している');
```

- 最初のページを無条件に使わない。オリジンとパスで対象のページを選ぶ。ログインの途中は認証のページがあり、ログインの後に選び直す
- 対象の画面に着いたら、環境のホスト、画面のパス、見出しに加え、アプリが渡す host object（例 `window.chrome.webview.hostObjects`）があることを確かめる。通常のブラウザに差し替えたり、host object や API の応答をモックしたりして成功させない
- `browser.newContext()` で別のコンテキストを作らない。アプリの中の画面ではなくなる
- Playwright のテストでは、通常の `page` のフィクスチャを、この接続のページに置き換えるフィクスチャを作る。設定は Web のテストと分け（例 `playwright.webview2.config.ts`）、`workers: 1` で流す
- `browser.close()` は接続を切るだけで、アプリは終わらない

## ログイン

WebView2 のアプリでは、ログインはアプリの中で行う。ブラウザで作った storageState をコピーしても、アプリのログイン状態にはならない。起動のたびに閲覧データを消すアプリもある。

- アプリの中の Web のログイン画面なら、接続したページでログインする。資格情報はプロファイルの `roles` に名前がある環境変数から読む。ログインの判定の基準は aidev-qa-login-session と同じにする
- ネイティブのログイン画面なら、aidev-qa-desktop-gui で起動とログインを行い、そのプロセスの ID とポートを受け取って接続する。受け取ったら、ログインした先が対象の環境のページであることを確かめてから始める
- エージェントの安全の決まりでパスワードを自動で入れられない環境では、決まりを回避しない。テスト用のインスタンスを起動し、どのウィンドウ（プロセスの ID）にどのロールでログインするかを作業者に示して、ログインしてもらう。資格情報の値を会話に出させない。`/json/list` に対象のページが出るまで期限付きで待ち、手動でログインしたことを記録に残す
- ログインに失敗した、接続したページがログイン画面のまま、という場合は、その実行のケースをすべて実行不能（認証の準備に失敗）にする
- 実行中にログイン画面に戻された（セッション切れ、証明書のエラー）ら、そのケースを止めて、ログインからやり直す。戻されたこと自体をそのケースの結果に書く

ログインの後の URL にトークンが付くアプリがある。記録や報告に URL を書くときは、クエリの値を伏せる。

## ブラウザとの違い

- 画面のサイズは、アプリのウィンドウの大きさで決まる。スクリーンショットを比べる環境どうしで、解像度、DPI、ウィンドウの大きさ、表示倍率をそろえ、実際の大きさを記録する。そろえるために作業者のウィンドウを勝手に動かさない
- 帳票のダウンロードは、アプリの設定によって OS の保存ダイアログになる。ダイアログが出るなら `native-required` である
- API の要求は、アプリの中継（クライアント証明書の転送など）を通っても、`page.on('request')` と `page.on('response')` で見えることが多い。見えない場合は API の記録の制約として残す
- 終了するのは、今回起動したプロセスだけにする。同じ名前のプロセスをまとめて終了させない。ウィンドウを閉じる操作（`CloseMainWindow()`）で終わらせ、強制終了は避ける。閉じるときに閲覧データの消去や保存が走るアプリがある
- 更新の途中、保存していない変更がある、状態が分からない、というときは終了させない。ケースを保留にし、状態と必要な対応を作業者に伝える
- テスト用のインスタンスは、時間がたつと記録を残さずに終わることがある。各実行の前にプロセスが生きていることと、`/json/list` に対象のページがあることを確かめ、消えていれば起動とログインからやり直す。前の結果を流用しない
