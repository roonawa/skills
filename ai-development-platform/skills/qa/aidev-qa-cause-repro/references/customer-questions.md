# 顧客への質問の書き方

症状だけでは原因を1つに絞れず、顧客や報告者に追加の情報を頼むときに読む。質問を受け取るのは、業務には詳しいが IT には詳しくない人であることが多い。答えやすい質問ほど、早く正確な回答が返ってくる。

## 何を聞くかを先に決める

質問を書く前に、残っている候補の原因と、それぞれを確かめる・外すのに要る事実を並べる。聞くのは、その事実のうち、コードやテスト用の環境では分からないものだけにする。コードを読めば分かること、プロファイルや設計書に書いてあることは聞かない。

質問の数は、候補を絞るのに要る分にとどめる。目安は3問から5問である。多すぎると答えてもらえず、少なすぎるともう一往復が要る。

## 1問に1つのことを聞く

「いつ、どの画面で、何をしたら、どうなりましたか」と1問にまとめると、答えの一部が抜ける。1つの質問では1つのことだけを聞き、番号を付ける。選んで答えられるものは選択肢を示す（「毎回ですか、ときどきですか」）。

## 専門用語を画面と操作の言葉に言い換える

| 避ける聞き方 | 言い換えた聞き方 |
|---|---|
| エラーメッセージやスタックトレースを教えてください | 画面に赤い字や警告で出ていた文言を、そのまま一字一句教えてください。画面の写真やキャプチャをいただけると助かります |
| リクエストのパラメータを教えてください | その操作をしたときに、画面で入力したり選んだりしていた項目と、その内容を教えてください |
| 対象のレコードの ID を教えてください | 問題が起きたデータについて、画面に表示されている番号（申込番号、受付番号など）を教えてください |
| 再現手順を詳しくしてください | もう一度同じ操作をすると、毎回起きますか、ときどきですか |
| 発生した環境はどこですか | ふだんお使いの画面で起きましたか、それとも確認用（テスト用）の画面ですか |
| ブラウザとバージョンを教えてください | 画面を開くときに使っているソフト（Edge、Chrome など）と、パソコンかタブレットかを教えてください |
| キャッシュをクリアして再試行してください | （質問にしない。作業をお願いすると、元の状態が分からなくなる） |

送る前に読み返し、英字の略語、カタカナの技術用語、システムの内部の名前（テーブル名、関数名、画面の内部の名前）が残っていないかを見る。画面の名前は、顧客が画面で見ている表記に合わせる。

## なぜ聞くのかを一言添える

質問ごとに、その答えで何が分かるかを一言添える。理由が分かると、答える人は関係のありそうなことを補って書いてくれる。

- 「どのデータで起きるかを絞り込むために、画面に出ている番号を教えてください」
- 「操作の順番で結果が変わる可能性があるため、保存の前にほかのボタンを押していたかを教えてください」

報告書の側には、質問ごとに、答えによって候補がどう変わるか（「毎回なら候補 A、ときどきなら候補 B が有力」）を書いておく。回答が来たら、それに従って SKILL.md の進め方の 3 からやり直す。顧客に送る文面には、候補の原因やコードの話を書かない。

## 個人情報は要る分だけを聞く

- データを特定するには、画面に出ている番号を聞く。氏名、住所、生年月日などの個人の値は、番号で特定できないときに限り、要る項目だけを聞く
- 画面の写真やキャプチャを頼むときは、氏名などの個人の情報が写っていれば、その部分を隠してよいと添える
- パスワード、ログインの ID、認証のコードは聞かない。送られてきても報告書や Issue に写さず、作業者に伝える
- 受け取った回答に個人情報が含まれていても、報告書と Issue には性質だけを書く（「氏名に旧字体を含む記録」）

## 文面の例

```text
お問い合わせいただいた「一覧が空で表示される」件について、原因を絞り込むため、次の点を教えていただけますか。

1. 一覧が空になったとき、画面の上の検索の欄には何を入力していましたか。何も入れずに検索した場合は「空のまま」とお書きください。
   （条件によって表示の仕方が変わるため、同じ条件で確かめたいと考えています）
2. 同じ操作をもう一度すると、毎回空になりますか、ときどきですか。
3. 空になった日と、だいたいの時刻を教えてください。
   （その時間帯に何が起きていたかを確かめるためです）
4. 画面に何か文言が出ていれば、そのまま教えてください。画面の写真でもかまいません。お名前などが写っている場合は、その部分を隠していただいてかまいません。

お手数をおかけしますが、よろしくお願いいたします。
```
