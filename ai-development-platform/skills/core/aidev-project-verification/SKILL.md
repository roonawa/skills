# プロジェクトの配置確認

## Overview

配布した Skill のコピー（`.claude/skills/NAME/SKILL.md` と `.agents/skills/NAME/SKILL.md`）は、原本と同じ内容であることが前提で、`verify` はその一致を確かめる。**コピーを書き換えると、以後 `verify` は必ず失敗する。** プロジェクト固有の決まり（使うテストランナー、ファイルの置き場所）は Skill ではなく AGENTS.md に書く。利用者の変更や削除が絡む操作は、内容を確かめて退避し、担当者の了承を得てから行う。

## When to Use

- `aidev verify`・`aidev skill add`・`aidev doctor` がエラーになった
- Skill が見つからない、古い、両ホストで内容が違う
- 配布された Skill を上書き・追記したいと言われた

**対象外：** アプリのテスト失敗や不具合 → aidev-debugging。Skill の内容の改善 → aidev-skill-evolution。

## CLI の呼び出し

本文の `aidev …` は、AGENTS.md の「aidev CLI の呼び出し方」に従い `node $env:AIDEV_CLI …`（PowerShell）または `node "$AIDEV_CLI" …`（bash/zsh）として実行する。AIDEV_CLI が未設定、または指すファイルがない場合は、パスを推測・探索せず担当者に確認する。プロジェクト直下で実行する。各コマンドは JSON を標準出力に返し、成功は終了コード 0、失敗は 1。

## Core Pattern

**Before**：「verify がエラー。面倒なら上書きでいい」に対し、改名の指示に従って新名を追加し、旧名を削除する。`.agents/skills/testing/SKILL.md` に開発者が書き足した 3 行は、新しい版の Skill に書き戻す計画にする。書き戻した時点で verify は内容差で失敗し続ける。

**After**：エラーを一つずつ解消し、そのたびに verify を再実行する（verify は最初の問題で止まるため）。開発者の追記 3 行は、AGENTS.md に移す案として担当者に示し、了承後に移す。旧名の配置は差分を確かめて退避してから、担当者の了承を得て削除する。

## エラーごとの対応

| verify・add のエラー | 意味 | 対応 |
|---|---|---|
| `Skill X は aidev-X に改名されました` | 旧名で登録されたままの Skill がある | `aidev skill add aidev-X --dry-run` → 了承後に add。旧名の配置と `.aidev/installed/X` は差分を確かめて退避し、了承を得て削除 |
| `配置ファイルが不足しています: …` | 片方または両方のコピー、版の記録が欠けている | `aidev skill add NAME --dry-run` で補う対象を確認してから add |
| `既存ファイルと競合しています: …` | コピーが原本と違う（利用者の変更、または古い版） | 下の「内容差の扱い」へ。上書きしない |
| `同梱 Registry にない Skill が登録されています: …` | 基盤側に存在しない名前が登録されている | 基盤の版と `skill list` を確かめ、担当者に報告 |
| `プロジェクト直下で実行してください` | aidev.json が無い場所で実行した | プロジェクト直下に移動する |
| `リンクを含む配置先は使用できません` | 配置先にシンボリックリンク・ジャンクションがある | リンクを外すかどうか担当者に確認する。CLI はリンク先に書き込まない |

## 手順

1. `aidev doctor` で、設定と同梱 Registry を読めることを確かめる。
2. `aidev verify` を実行する。エラーなら上の表で対応を決める。
3. 書き込みを伴う操作（add）は、先に `--dry-run` で対象を確認する。
4. 一つ解消したら verify を再実行する。成功（終了コード 0、`skills` に対象名がある）まで繰り返す。
5. 削除・移動・AGENTS.md への追記は、対象と差分を示して担当者の了承を得てから行う。

## 内容差の扱い

1. 原本との差分を取る。原本は基盤の `skills/core/NAME/SKILL.md`（基盤は AIDEV_CLI が指す `dist/cli.js` の二つ上のディレクトリ）。
   ```bash
   git diff --no-index <基盤>/skills/core/NAME/SKILL.md .agents/skills/NAME/SKILL.md
   ```
2. 差分を分類する。
   - **古い版**（`.aidev/installed/NAME` の版が原本より古く、利用者の追記が無い）：担当者の了承を得て、コピーを退避してから削除し、`skill add` で配り直す。
   - **利用者の追記**（プロジェクト固有の決まり）：AGENTS.md に移す案を示す。了承後に AGENTS.md へ移し、コピーを退避してから配り直す。
   - **Skill 自体の改善**（全プロジェクトに役立つ変更）：aidev-skill-evolution で原本の改訂として提案する。
3. 「上書きでいい」と言われても、追記を含むコピーは退避と移し先の確認なしに上書きしない。

## 報告の型

1. 実行したコマンドと終了コード（JSON の `ok`・`error`）
2. 見つかった問題と、その対応（実施済み／了承待ち）
3. 退避したファイルの場所
4. AGENTS.md に移した、または移す案の内容
5. 最終的な `verify` の結果

## よくある言い訳と実際

| 言い訳 | 実際 |
|---|---|
| 「上書きでいいと言われた」 | 追記が消えると、プロジェクト固有の決まりが失われる。退避して移し先を決めてから配り直す |
| 「追記は新しい版の Skill に書き戻せばよい」 | 書き戻したコピーは原本と一致せず、verify が失敗し続ける。決まりは AGENTS.md に書く |
| 「一つ直したので verify は通るはず」 | verify は最初の問題で止まる。再実行して確かめる |
| 「旧名は不要なので消してよい」 | 旧名のコピーにも利用者の追記があるかもしれない。差分を確かめて退避する |

## Red Flags

- 配布された Skill のコピーを直接編集しようとしている
- `--dry-run` を経ずに add を実行しようとしている
- 了承を得ずに削除しようとしている
- verify を再実行せずに完了と報告しようとしている

## 完了条件

- [ ] `aidev verify` が終了コード 0 で、対象の Skill が `skills` に含まれる
- [ ] 内容差は分類し、利用者の追記は AGENTS.md に移した（または了承待ちとして報告した）
- [ ] 削除・上書きしたファイルは退避し、担当者の了承を得た
- [ ] 報告の型どおりに、コマンド・終了コード・対応・退避先を報告した
