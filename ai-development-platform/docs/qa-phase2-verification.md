# QA Skill 段階2の確認結果

実施日は 2026-11-18。設計は [QA Skill 汎用化の設計書](superpowers/specs/2026-11-18-qa-skills-generalization-design.md) にある。段階1と段階2の Skill を、見本の2案件で通しで動かした。

## 方法

見本 Web は旧版（ポート 4101）と新版（ポート 4102）を起動した。`aidev init qa-web --template qa` で一時リポジトリを作り、要件定義書、プロファイル、AC を写して、段階1と段階2の Skill をすべて入れた。

各工程は、互いに独立したセッション（サブエージェント、Sonnet）で順に行った。人が答える場面は、QUESTIONS.md に質問と仮の判断を書いて先へ進める指示にした。見本アプリには作った行を消す機能がないため、工程の間でデータをそろえるために見本アプリを起動し直した。

見本 Desktop は、利用者の了承を得て画面を占有して流した。占有した時間は約11分である。

## 見本 Desktop

12 ケースで OK 11、NG 0、実行不能 1 だった。実行不能は書き込めない保存先のケースで、見本アプリが落ちる既知の問題があったため対象外にした。

保存先の絶対パスを入力する方法で、一時フォルダーに保存できた。ダイアログが最初に開いたフォルダー（ドキュメント）、デスクトップ、ダウンロード、アプリのフォルダーに、新しいファイルはできていない。証跡はアプリの画面で、ロック画面ではない。後片付け（起動したプロセス、一時フォルダー）も確かめた。

この確認の後、保存に失敗しても落ちずにエラーのメッセージを出すように見本アプリを直した。直した後に、書き込めない保存先のケースは流していない。

## 確認で見つかった Skill の改善点

通しの実行で、Skill に書かれていない点や合わない点が34件見つかった。主なものは次のとおり。

- Playwright が実行のたびに test-results/ を消すこと
- 削除のできないアプリでの、データのそろえ方と流し直しの決まり
- Windows のコマンドプロンプトでの `--grep "a|b"`
- 一覧を位置で比べると、並び順の変更で照合が意味をなさないこと
- 認可の例が、NG の後の行を飛ばすこと
- 画面のロックの判定の誤検知
- デスクトップのテストのセッションの後片付け

これらは同じブランチの修正でまとめて直した。修正の内容は、各 Skill の版の更新とコミットにある。
