# 答え合わせ（見本 Web）

このファイルは Skill に渡さない。Skill が出した結果を、人が答え合わせに使う。

優先度を高とする期待は、先に aidev-qa-strategy が plan/strategy.md を作っている前提である。確認では aidev-qa-strategy から aidev-qa-test-design までを通しで動かす。plan/strategy.md がなければ、aidev-qa-test-design は優先度を推測せず、中にして「⚠ 要確認」を付ける。

## qa-test-design が必ず作るべき観点

次の観点が、各 AC に対応するテストケースとして出ていること。

AC-001 は正常ログインと失敗ログインの 2 本。AC-002 は未ログインの 4 つの URL。AC-003 は staff と admin で一覧の範囲が違うこと。AC-004 は 0 件の表示。AC-005 は 50 件、51 件の境界と最終ページ。AC-006 は並び順と、同じ貸出日の ID 順。AC-007 は詳細の項目。

AC-008 は staff が他人の貸出の URL を直接開く行レベルの所有者検証で、実行は自動、優先度は高にすること。AC-009 は admin が開けること。AC-010 は 404。AC-011 は必須の空と文字数の上限の境目。AC-012 は貸出日当日、30 日後、31 日後、貸出日の前日の境目。AC-013 は借りた人の記録。AC-014 は見出し行、列順、全員分の行、日付の形式。AC-015 は staff の CSV 直接アクセス。

## qa-test-review が指摘すべき欠落

レビュー用に、AC-008 と AC-015 に対応するケース、つまり staff が URL を直接開く権限のケースをわざと抜いたテスト仕様書を用意する。レビューは、AC-008（他人の貸出の詳細を staff が直接開く）に対応するテストが無いことを、重大な欠落として指摘すること。AC-015 も同様に指摘できればよい。画面のボタンが出ないことだけを確かめたケースで AC-008 を満たしたことにしていないかも見る。

## 旧版と新版の差（回帰照合で使う）

意図した差分は、一覧の並び順が貸出日の古い順から新しい順に変わったことで、AC-006 と対応する。要確認にしてはいけない。意図しない差分は、CSV の日付の形式が yyyy-MM-dd から yyyy/MM/dd に変わったことで、AC-014 に反する。照合は、これを意図した差分とは別に、要確認として挙げること。


わざと入れた不具合は、新版だけで staff が /loans.csv を直接開くと 403 ではなく CSV が返ることで、AC-015 に反する。旧版は 403 を返す。詳細画面の 403（AC-008）は両方の版で正しい。画面の「CSV 出力」ボタンは staff に出ないので、ボタンの有無を見るだけでは見つからない。URL を直接開いて確かめる必要がある。

回帰照合は、旧版と新版で staff の /loans.csv の応答が違うことを、意図した差分とは別に要確認として挙げること。認可の検証（aidev-qa-authz-test）は、staff の CSV 直接アクセスを新版の不具合として検出すること。詳細画面の 403 は、新旧どちらも期待どおりと判定すること。
