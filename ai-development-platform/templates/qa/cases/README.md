# テストケース

テストケースは cases/機能名.md に機能ごとにまとめます。ファイルの先頭には機能名の見出しと、ケースのもとにした文書を1行で書きます。ケースごとに次の形で書きます。

```
# 一覧

対象の設計書: 基本設計書 4.2

### TC-機能名-001 ケース名
- AC: AC-001, AC-002
- 優先度: 高
- 実行: 自動
手順
1. 一覧画面を開く
期待結果
- 0件のとき空表示になる
備考
- ⚠ 要確認: 空表示の文言は設計書に記載がない
```

TC-ID は TC-機能名-連番です。AC は対応する受け入れ条件の AC-ID をカンマで区切ります。優先度は高、中、低から選びます。実行は自動か手動です。

「対象の設計書:」の行には、ケースのもとにした設計書の名前と節を書きます。設計書がなくコードから仕様を推定した場合は、plan/inferred-spec.md の RS-ID を書きます。

備考は省略できます。書く場合は、ケースの最後（期待結果の後）に置きます。期待結果は、次の「備考」の行か、次のケースの見出しまでです。備考には「⚠ 要確認」や、推定した仕様と実装の挙動が食い違う「実装疑義」を書きます。
