# QA リポジトリ

このリポジトリは、1つの案件のテスト計画、テストケース、実行結果、報告書、案件ごとの知識をまとめて管理します。aidev-qa の Skill は、ここに置いたファイルを読み書きします。

## 構成

- plan/acceptance.md は受け入れ条件の一覧です。要件定義書から転記し、AC-ID を振ります。
- plan/inferred-spec.md は、設計書がなくコードしか手がかりがない案件でだけ作ります。コードから推定した仕様を、次の表で1行に1件書きます。確信度は高、中、低のどれかです。RS-ID は振り直しません。

  ```
  | RS-ID | 対象 | 推定した仕様 | 根拠 | 確信度 | 実装との差異 |
  |---|---|---|---|---|---|
  | RS-001 | ファイル名と関数名 | 推定した業務の規則 | 名前、入力チェック、DB の制約など | 中 | なし |
  ```

- cases/ にはテストケースを機能ごとのファイルで置きます。
- runs/ には実行ごとの結果と証跡を置きます。
- reports/ には報告書を置きます。
- knowledge/ には製品ごとの案件プロファイルを置きます。

各ディレクトリの README に、書き方を記載しています。

## 使い始め

knowledge/profile.template.md を knowledge/製品名/profile.md にコピーし、product を埋めます。その後に aidev check を実行すると、プロファイルを検査できます。パスワードやトークンの値は書かず、環境変数の名前だけを書いてください。

テストケースは受け入れ条件と対応づけます。AC-ID は aidev spec check と同じ AC-001 の形です。
